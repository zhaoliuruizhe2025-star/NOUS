# NOUS Expression Lab — Post-Beta Future Epic

## 1. Status

**POST-BETA / FUTURE.**

Expression Lab is not part of Task 002, the current implementation phase, or the active path to the first Private Beta. It remains in `docs/BACKLOG.md` until explicitly promoted through the task system.

## 2. Purpose

Expression Lab would help users express feelings and ideas they already have in language that feels like their own when the words are difficult to find.

Its goal is articulation, not fabrication. It must not invent affection, remorse, gratitude, commitment, or conviction that the user does not endorse.

## 3. Potential expression contexts

- romance;
- gratitude;
- apology;
- encouragement;
- friendship;
- family;
- birthday and anniversary;
- farewell;
- Physics;
- Mathematics;
- Chemistry;
- Astronomy;
- Biology;
- Computer Science;
- Philosophy;
- Literature.

These are future categories, not approved screens or implementation requirements.

### Technical correctness before metaphorical beauty

Scientific or mathematical expression lenses must remain conceptually accurate. They must not distort a technical concept merely to make a line sound romantic, profound, or elegant.

Metaphor may make an idea vivid, but technical correctness comes before metaphorical beauty.

## 4. Personalization boundary

When available and explicitly appropriate, Expression Lab may use:

- the user's own memories;
- the user's stated feelings and intent;
- the user's expression style;
- relationship context as the user described it;
- language and tone preferences.

It should prefer the user's actual history over generic invented anecdotes. It must distinguish between recalling the user's material and generating optional wording.

The user remains the author and final editor. Suggested text must be easy to revise or reject.

## 5. Safety and integrity boundaries

Expression Lab must not:

- fabricate feelings or memories;
- impersonate another real person's inner voice;
- infer a third party's hidden motives or emotions as fact;
- pressure the user to send generated text;
- create manipulative, coercive, deceptive, or abusive communication;
- silently write generated language back into the durable Self Model as the user's authentic belief;
- share content externally without an explicit user action.

An apology aid, for example, may clarify the user's acknowledged responsibility and intended repair; it should not manufacture remorse merely to make the message persuasive.

## 6. Relationship to NOUS

Expression Lab is downstream of the core loop:

```text
Remember -> Connect -> Reflect -> Self-awareness -> optional expression support
```

It should draw from a mature, user-correctable Self Model and reviewed interaction behavior. It is not a substitute for building the core self-awareness system.

## 7. Future design questions

Before implementation, a dedicated design task must address:

- consent and review before using personal memories;
- separation between user-authored and generated language;
- preservation of bilingual voice and personal style;
- safe handling of high-stakes messages;
- local-first generation options and any network implications;
- evaluation of authenticity without claiming to measure the user's “true” feelings.
